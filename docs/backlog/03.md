# [Week 1] Private database, authentication, profile, and preferences

## Summary

Let students sign in and manage **private travel preferences** while keeping public transit browsing open to everyone. Protect every personal table with ownership rules and provide a complete sign-out and account-deletion flow.

## Background

The starter supplies browser/server Supabase clients, session-refresh proxy, and an owner-only `profiles` table. Expand that foundation in `supabase/migrations/` and [`src/lib/supabase/`](https://github.com/nandanpraveen/ArchRide/tree/main/src/lib/supabase). Coordinate table shapes with tasks 7–10 and the admin access model with task 11.

This is a **Week 1** task, from **2026-10-11 to 2026-10-18**, with the Sunday handoff in **America/New_York**. Claim the draft in the project before starting.

## Requirements

- [ ] Finish email-based sign-up/sign-in, verification callback, resend, expired-link/error handling, session persistence/refresh, password recovery if passwords are chosen, and sign-out using Supabase Auth. Configure allowed redirects for local, preview, and production environments without open redirects.
- [ ] Extend profiles/preferences with display name, email display, default manual origin, walking pace, arrival/safety buffer, theme, notification types, quiet hours, and America/New_York schedule timezone. Validate bounded values on the server.
- [ ] Provide migrations and generated types for favorites, named saved trips, classes, active trip sessions, reminder jobs, notifications, and push subscriptions if supported. Use owner IDs, foreign keys, appropriate indexes, uniqueness, timestamps, and cascades.
- [ ] Enable RLS on every exposed table and explicit minimal grants. Test SELECT, INSERT, UPDATE, DELETE and attempted ownership reassignment. Public transit is readable by guests; private rows belong only to their user.
- [ ] Finish Profile UI, shared preference application, links to saved items/classes/notifications, and guest-to-sign-in entry points. The theme preference affects the complete shell and contrast is checked in each supported theme.
- [ ] Implement confirmed account deletion through an authenticated server-only operation: verify current identity, revoke/sign out sessions, remove owned records and subscriptions, and delete the Auth account. Treat still-valid access tokens as a deletion test case.
- [ ] Keep secret/service-role credentials outside browser code. Use validated server identity and trusted admin roles; never authorize from editable user_metadata.
- [ ] Document location/privacy behavior, personal-data retention, account deletion, and the student-built affiliation statement in the app.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build` pass. Add meaningful feature tests, including the cases below.

## Out of scope

- University SSO/course import, additional social providers, or storing a continuous location trail.
- Implementing the favorites, schedule, and reminder feature screens owned by later tasks.

## What we'll test

- Guest access to all public transit screens; private requests rejected when signed out.
- Sign-up, verified and expired links, invalid redirects, duplicate email, sign-in failure, refresh, multiple tabs, sign-out, and recovery.
- Two independent users cannot read or change each other’s records by guessing IDs; anonymous access and owner-ID changes fail.
- Invalid preference limits, saved defaults, theme persistence, keyboard forms, and quiet hours crossing midnight.
- Account deletion cancels jobs/subscriptions and removes personal rows; another user survives; old tokens cannot recreate or read private data.
