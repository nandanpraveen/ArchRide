# [Week 2] Weekly class schedule and next-class travel planning

## Summary

Let students manually enter a **weekly class schedule** and use it to plan their next campus trip. Surface the next class on Home and calculate when to depart when an origin and enough transit data are available.

## Background

Task 3 owns private class tables and preferences; task 5 plans journeys; task 6 assesses time and data validity. Task 10 delivers reminders. Campus class times use America/New_York regardless of the phone’s current timezone.

This is a **Week 2** task, from **2026-10-18 to 2026-10-25**, with the Sunday handoff in **America/New_York**. Claim the draft in the project before starting.

## Requirements

- [ ] Build a Material schedule editor and weekly list for class label, verified building/entrance, weekday(s), local start time, arrival buffer, enabled state, and reminder toggle per class.
- [ ] Allow create, edit, duplicate if useful, and delete with confirmation/undo. Validate missing destinations, bounded buffers, valid local times, and repeated weekday values.
- [ ] Compute the next occurrence in America/New_York, preserving wall-clock class time across daylight saving changes. Specify behavior for simultaneous classes, overlapping entries, and classes already started.
- [ ] Show the next enabled class/destination on Home with a Plan action. Use a known manual/default/GPS origin without silently assuming the user is at their last class.
- [ ] Calculate a suggested leave time from the complete supported journey and class arrival buffer. If future transit predictions are unsupported, expose the limitation and a supported walk estimate rather than inventing future bus timing.
- [ ] Sync signed-in schedules privately through Supabase; give guests a clear sign-in path for schedule synchronization. Never fetch private university course information.
- [ ] Expose a timezone-aware next-occurrence and reminder-job contract for task 10. Editing/removing/disabling a class invalidates obsolete reminder jobs.
- [ ] Link classes from Profile and cover empty, save failure, unavailable building, invalidated destination, and network-loss states.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build` pass. Add meaningful feature tests, including the cases below.

## Out of scope

- University login, course scraping/import, academic calendar inference, or claiming knowledge of cancellations/holidays.
- Background reminders themselves; task 10 owns delivery.

## What we'll test

- One class, multiple weekdays, weekend classes, same-time classes, overlapping classes, disabled classes, and no future class this week.
- Sunday-to-Monday rollover, midnight, before/after class start, buffer larger than available time, and November 1 daylight-saving transition.
- A phone in a different timezone still shows the correct campus schedule time.
- Editing time/building or deleting a class updates Home and cancels its old reminder; a retired building is recoverable.
- Unknown origin, denied GPS, unsupported future bus predictions, offline save retry, and cross-user privacy.
