# [Week 1] Material Design shell, campus search, and Home dashboard

## Summary

Build the mobile-first **Home** experience and shared Material Design navigation. A student should be able to find a campus building or stop, open the map, and understand the best available next action without interpreting raw transit data.

## Background

The starter in [`src/components/`](https://github.com/nandanpraveen/ArchRide/tree/main/src/components) provides a Material shell and five destinations. The agreed design lives in `DESIGN.md`. Coordinate the public data contract with task 2 and wire its verified locations into this screen before closing the task. Tasks 7 and 8 later supply personalized Home sections.

This is a **Week 1** task, from **2026-10-11 to 2026-10-18**, with the Sunday handoff in **America/New_York**. Claim the draft in the project before starting.

## Requirements

- [ ] Use Material UI controls and shared tokens for Home, Map, Plan, Saved, and Profile. Add responsive route/stop detail, alerts, notifications, and active-trip entry points without adding competing navigation.
- [ ] Implement keyboard-accessible, debounced search across verified buildings, entrances, and stops. Show the result type and location; selecting a result opens details or pre-fills Plan.
- [ ] Offer optional location access with an explanation and manual building/stop origin fallback. Request permission only after a user action; do not store continuous location history.
- [ ] Show nearby stops and available departures, a next-trip recommendation when an origin and destination are known, favorite shortcuts, and the next-class slot. Wire favorites and classes to tasks 7 and 8 rather than inventing data.
- [ ] Display relevant alerts and shared freshness/provenance labels. No source data means a useful unavailable state, not example buses or fake countdowns.
- [ ] Finish loading, empty search, offline, stale data, denied-location, retry, and signed-out states. Home remains useful without an account.
- [ ] Make Home and the shared shell usable from 320 px through desktop, with 48 px primary touch targets, visible focus, accessible labels, adequate contrast, safe-area padding, and reduced motion.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build` pass. Add meaningful feature tests, including the cases below.

## Out of scope

- Implementing the transit importer, trip algorithm, or saved-item storage; their owners provide the data contracts.
- University account integration or unsupported official UGA branding.

## What we'll test

- Search with spaces, capitalization, aliases, duplicate building names, no results, a long result name, and a rapidly changed query.
- Location allowed, denied, unavailable, timed out, and outside the supported campus area; manual origin still works.
- Guest Home, a returning user, no nearby stops, no active service, source outage, and delayed responses arriving out of order.
- All five destinations, browser Back/Forward, direct links, keyboard-only search and navigation, screen-reader labels, and 320 px layout.
- Favorites and the next-class entry appear once tasks 7 and 8 integrate; opening them uses current data.
