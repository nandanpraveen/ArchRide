# [Week 3] Leave-now reminders and notification center

## Summary

Build **in-app leave-now reminders** and a notification center for trips, classes, and relevant service alerts. Background web push is included only for verified supported browsers/devices and must never be promised when delivery is unavailable.

## Background

Task 8 supplies recurring classes, task 9 supplies active-trip events, and tasks 5–6 supply walking time and valid estimates. Reuse task 3’s private reminder/notification tables and preferences. Clarify the in-app-only experience before implementing optional push.

This is a **Week 3** task, from **2026-10-25 to 2026-11-01**, with the Sunday handoff in **America/New_York**. Claim the draft in the project before starting.

## Requirements

- [ ] Compute leave-now time from boarding time minus walk-to-stop and the configurable safety buffer, or from a valid walk-to-class plan. Recompute when source changes affect feasibility.
- [ ] Deliver in-app reminders while the app is active, with notification center history, read/unread, clear/expiry behavior, timestamps, links to the affected trip/class/alert, and a useful empty state.
- [ ] Support per-class toggles, per-type preferences, quiet hours crossing midnight, timezone-aware timing, and account-wide notification settings in Profile.
- [ ] Schedule trusted server jobs only where needed using Supabase Cron/Edge Functions and owner-only data. Use a deterministic deduplication key, retries with bounds, cancellation, expiry, and clock-controlled tests.
- [ ] Cancel or replace obsolete jobs after class edits/deletion, trip end/reroute, preference changes, sign-out where appropriate, and account deletion. Never send expired leave-now prompts.
- [ ] Assess and document the browser/device support matrix for web push, including iOS installation requirements. If supported targets are chosen, implement HTTPS/service worker, explicit opt-in, subscription storage, server-only push keys, revocation, and failure cleanup.
- [ ] On unsupported devices or denied permission, provide an honest in-app-only explanation. Do not request notification permission on first page load or claim reminders work after the app closes without a verified push path.
- [ ] Keep lock-screen content minimal and private; cross-user subscriptions and notifications must be inaccessible. Integrate Home and active-trip notification entry points.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build` pass. Add meaningful feature tests, including the cases below.

## Out of scope

- Native mobile apps, SMS/email reminder services, or guaranteed OS-level notification delivery.
- Background push on browsers/devices that cannot support the verified implementation.

## What we'll test

- A reachable bus, a changed ETA, a missed bus, walking-only class reminder, and stale/missing ETA without a made-up leave time.
- Exact reminder boundary, late job, duplicate/retried job, browser sleep/resume, clock skew, and expired notifications.
- Quiet hours across midnight, timezone differences and daylight saving, per-class disabled state, and preference changes after scheduling.
- Class deletion, trip cancellation, account deletion, sign-out/account switch, invalidated push subscription, and two-user access tests.
- Permission allowed/denied/revoked, unsupported browser, offline, installed versus uninstalled iOS web app, and in-app fallback.
