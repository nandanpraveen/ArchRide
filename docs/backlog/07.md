# [Week 2] Guest favorites and synced named saved trips

## Summary

Let students save **favorite stops** and **named journeys**, manage them on Saved, and reuse them from Home. Opening a saved journey must plan against current information instead of replaying an old bus choice.

## Background

Use task 3’s private tables and Auth, task 4’s stop details, and task 5’s planner. Guests use local storage; signed-in users sync through Supabase. Integrate the favorite and saved-trip slots left by task 1 before closing this task.

This is a **Week 2** task, from **2026-10-18 to 2026-10-25**, with the Sunday handoff in **America/New_York**. Claim the draft in the project before starting.

## Requirements

- [ ] Add save/unsave actions to stop details and trip results. Save journey origins/destinations and preferences, not an expiring vehicle or prediction.
- [ ] Build the Saved page with stop favorites, named journeys, rename, reorder, remove with useful feedback/undo, and links to the correct stop or fresh Plan result.
- [ ] Support guests with versioned local data and signed-in users with owner-only Supabase rows. Explain that guest items stay on the current device.
- [ ] On sign-in offer a clear merge/import of guest items, deduplicate equivalent stops/journeys, retain valid names/order, and avoid silently overwriting cloud items.
- [ ] Handle optimistic updates, server rejection, retries, concurrent tabs/devices, signed-out state, and network loss without losing a successful change.
- [ ] Populate Home favorites/recent saved-journey actions and reflect rename/reorder/removal across the app.
- [ ] Handle retired stops/buildings, changed route patterns, and corrupted/old local records. Mark invalid saved items and let the student repair or remove them.
- [ ] Keep personal items off shared caches and out of another user’s session after account switching or deletion.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build` pass. Add meaningful feature tests, including the cases below.

## Out of scope

- Saving historical live bus choices or sharing a student’s private journey list publicly.
- A second authentication system or a custom synchronization backend.

## What we'll test

- Guest refresh, blocked/full local storage, corrupted JSON, schema upgrade, duplicate save, and empty Saved.
- Rename to blank or a long value, reorder by keyboard, remove/undo, and undo after the server rejects an update.
- Two devices update the same item, offline retry, sign-out/sign-in to a different account, and two-user RLS attacks.
- Guest/cloud merge with duplicate journeys, differently named journeys, cancelled merge, and invalid source IDs.
- A saved journey opened later uses current arrivals; expired/deleted routes do not produce a stale recommended bus.
