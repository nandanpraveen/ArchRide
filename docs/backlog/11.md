# [Week 3] Restricted admin tools, maintenance, and data-quality operations

## Summary

Give trusted maintainers a small **restricted admin screen** for feed health, failed jobs, data corrections, manual notices, and prediction evaluation. Make routine maintenance safe enough for the team to operate after launch.

## Background

Tasks 2, 6, and 10 create the importer, evaluation records, and reminder jobs. Task 3 owns identity and trusted admin authorization. Prefer a focused `/admin` surface and existing Supabase operations over a new generalized admin platform.

This is a **Week 3** task, from **2026-10-25 to 2026-11-01**, with the Sunday handoff in **America/New_York**. Claim the draft in the project before starting.

## Requirements

- [ ] Protect admin pages and every backing server operation with server-validated identity and a trusted admin role stored outside editable user metadata. Non-admin authenticated users and guests have no admin access.
- [ ] Show last attempted/successful ingestion, feed freshness, safe error summaries, failed/retried jobs, source rate-limit state, and current retention/storage usage. Do not expose secrets or private student travel data.
- [ ] Offer bounded, audited retry controls that respect importer/job concurrency and upstream quotas. A repeated click must not create duplicate workers or reminder delivery.
- [ ] Support verified building/entrance corrections with validation and audit fields. Keep manual overrides separate from imported source values so the next import does not silently erase them.
- [ ] Create/edit/expire clearly labeled manual notices with affected routes/stops, valid-from/until, author, and provenance. Never display them as agency notices.
- [ ] Expose task 6’s evaluation report with sample counts and limits; unmeasured prediction quality remains explicitly unmeasured.
- [ ] Implement and verify scheduled retention cleanup, failed-job handling, revoked subscription cleanup, and useful indexes/query plans. Document backup/export and restoration options available on the actual plan.
- [ ] Write an operations runbook covering source outage, stale feed, quota exhaustion, lost worker credentials, data correction, rollback, restore, and account deletion. Add logs/alerts that avoid personal data.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build` pass. Add meaningful feature tests, including the cases below.

## Out of scope

- Broad access to personal schedules/location data, a public admin account, or a new analytics product.
- Buying a higher plan or changing unrelated Supabase projects.

## What we'll test

- Guest, ordinary user, forged client role/user_metadata, expired token, and trusted admin on both pages and direct API calls.
- Retry double-click/concurrent runs, quota response, job failure/recovery, invalid correction, and import after a correction.
- Manual notice before start, at expiry, with invalid dates/IDs, and clearly different from a source notice.
- Retention deletes only expired eligible history, keeps latest state and required personal records, and stays within free-plan budgets.
- Logs contain no credentials or private trips; an actual documented backup/restore drill and reversible deployment rollback are recorded.
