# [Week 1] Verify UGA data access and build central transit ingestion

## Summary

Connect **real UGA transit data** to Supabase through one centrally scheduled importer. Preserve source identity and timing so every screen can tell the difference between current, stale, and missing information.

## Background

UGA links its public bus tracker at routes.uga.edu, but that alone does not establish permission to reuse a private endpoint. Resolve data access at the start of this week. The starter has `feed_status`, `/api/health`, and checked-in Supabase migrations. Agree the route, stop, arrival, alert, and freshness contracts with tasks 1, 3, and 4.

This is a **Week 1** task, from **2026-10-11 to 2026-10-18**, with the Sunday handoff in **America/New_York**. Claim the draft in the project before starting.

## Requirements

- [ ] By October 12, document the authorized transit source, permitted use, endpoint/credential requirements, fields, update frequency, quotas, attribution, and evidence of access. Identify a real approved alternative if needed. Escalate blocked access immediately; fixture-only operation cannot satisfy the release gate.
- [ ] Create migrations and generated types for buildings/entrances, routes, direction/variant patterns, stops, ordered stop occurrences, operating schedules when available, latest vehicles, historical observations, arrivals, observed arrival events, walking-cache entries, alerts, and affected entities. Coordinate private tables with task 3.
- [ ] Preserve upstream IDs, route-pattern and stop-sequence identity, source timestamps, receipt timestamps, and agency timezone. A loop can visit one stop more than once.
- [ ] Implement a server-side Supabase Edge Function or equivalent trusted worker to fetch, validate, normalize, and upsert shared data centrally. Keep credentials server-only and public reads protected with explicit grants and RLS; guests cannot write transit data.
- [ ] Schedule ingestion within verified source and free-plan limits. Prevent overlapping runs, bound request timeouts/retries, use backoff on rate limits, and make replay idempotent.
- [ ] Keep the last valid snapshot through partial failures. Mark its freshness truthfully; missing vehicles alone never imply a cancelled route. Reject malformed coordinates, foreign IDs, and old updates that would overwrite newer state.
- [ ] Expose source-provided arrivals and supported service alerts without creating unsupported estimates. Publish typed read contracts and sanitized fixtures for teammates, clearly separate from production data.
- [ ] Set explicit configurable retention and scheduled cleanup for observations, arrival events, old predictions, and walking caches. Keep latest state separate from history and record safe job-health diagnostics.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build` pass. Add meaningful feature tests, including the cases below.

## Out of scope

- Scraping protected endpoints or bypassing source access restrictions.
- Custom machine-learning predictions, or claiming source accuracy before evaluation.

## What we'll test

- A real authorized successful ingestion and a repeated identical run; no duplicate rows or repeated-stop collisions.
- HTTP 429, 500, timeout, malformed JSON, partial source responses, no buses, old/out-of-order timestamps, and recovery after an outage.
- Coordinates at zero, missing route/direction, unknown stop IDs, repeated loop stops, cross-midnight service, and explicit source cancellation versus absence.
- Multiple visitors share the same cached feed; upstream requests do not multiply per browser.
- Guest read access, denied browser writes, no secrets in responses/bundles/logs, bounded database growth, and retention preserving latest state.
