# [Week 3] Production deployment, full-app testing, and ship gate

## Summary

Deploy ArchRide and verify the **whole agreed app** is ready to ship by the November 1 handoff. Closing this task means a working production URL, real authorized transit data, passing checks, and completed user journeys—not a successful build of placeholder screens.

## Background

All tasks 1–11 must be integrated before the release is accepted. The repository’s [CI workflow](https://github.com/nandanpraveen/ArchRide/blob/main/.github/workflows/ci.yml), `docs/APP_BRIEF.md`, and roadmap coverage matrix define the release baseline. Assign a release owner, but the team fixes defects in their own features.

This is a **Week 3** task, from **2026-10-25 to 2026-11-01**, with the Sunday handoff in **America/New_York**. Claim the draft in the project before starting.

## Requirements

- [ ] Deploy a production Next.js build to an agreed suitable host, connect the ArchRide Supabase project, configure server secrets, Auth redirects/site URL, scheduled ingestion/jobs, HTTPS, and any supported push keys. Use no paid upgrades without explicit approval.
- [ ] Complete every requirement from tasks 1–11 and remove visible starter placeholders, fake/live-demo data, dead controls, and unresolved ship-blocking TODOs from production. Every brief feature has an owner and a verified outcome.
- [ ] Run the full guest journey: search building → compare walking/bus → verify boarding direction → start trip → leave-now reminder → recovery/arrival. Run signed-in favorites, schedule, preferences, sign-out, and account deletion on production.
- [ ] Add integration/security coverage with two separate users and anonymous access, direct admin API attacks, all exposed tables/RLS/grants, session refresh, and post-deletion tokens. Confirm no secret key in browser assets, source control, responses, or logs.
- [ ] Test Home, map, route/stop details, Plan, Saved, Profile, alerts, notifications, classes, admin, and active trips on current target desktop/mobile browsers. Include real iPhone/Safari and Android/Chrome smoke tests, keyboard/screen-reader flows, 320 px width, contrast, reduced motion, and safe areas.
- [ ] Exercise denied GPS, outside-campus origin, slow/offline network, source outage/stale data, rate limits, no buses, malformed records, unreachable boarding, unsupported future trips, timezone/DST, expired jobs, denied push, and refresh/reopen recovery.
- [ ] Check real feed freshness and request volume, database growth/retention, walking/map provider quotas/attribution, loading performance, API timeouts, and useful production health monitoring. Record evidence rather than claiming measured accuracy without data.
- [ ] Publish a concise privacy/location notice, student-built affiliation statement, supported-browser/push limitations, README onboarding, operations/rollback runbook, release notes, production URL, and ownership for ongoing operation.
- [ ] Run CI on the final release commit, perform a production smoke test and rollback check, tag the release, and record the acceptance checklist and known non-blocking limitations. Any broken core journey or unapproved data access keeps this task open.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build` pass. Add meaningful feature tests, including the cases below.

## Out of scope

- New features beyond the approved brief, app-store packaging, or promising transit accuracy/notification delivery guarantees.
- Calling a demo complete while a required feature, live-data access, security check, or production deployment is missing.

## What we'll test

- Every feature in the coverage matrix has a reproducible passing acceptance result on the final commit.
- Guest and two-user end-to-end flows including account switching, deletion, private-data isolation, and direct admin access attempts.
- Real device/browser matrix, accessibility, narrow layouts, navigation/deep links, loading and all unavailable states.
- Source failures/recovery, reminders after edits, missed-bus alternatives, loop directions, daylight saving on November 1, and cold production requests.
- Clean-machine setup from README, successful CI, production health/feed checks, rollback, restored operation, and no credentials in Git history or shipped assets.
