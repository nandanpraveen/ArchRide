# [Week 1] Live map, route directory, and boarding-stop details

## Summary

Build the **Map**, route directory, route details, and stop details so students can identify the correct bus and boarding point. Use real source positions and label stale locations clearly.

## Background

Use task 2’s normalized public data and coordinate search/detail navigation with task 1. The starter Map page is intentionally empty. Choose a maintained map renderer and an authorized tile provider, document attribution and limits, and keep maps client-side where required by Next.js.

This is a **Week 1** task, from **2026-10-11 to 2026-10-18**, with the Sunday handoff in **America/New_York**. Claim the draft in the project before starting.

## Requirements

- [ ] Render verified route paths, stops, and latest vehicles on a pannable mobile map. Keep consistent labeled route colors across filters, map, Home, and details.
- [ ] Add route filters, selected vehicle/stop detail panels, optional user-location recentering, and a list alternative for keyboard and screen-reader users. Do not demand location permission to browse.
- [ ] Build a searchable route directory with route direction/variant, ordered stop occurrences, available operating information, path, and affected alerts.
- [ ] Build stop details with boarding location, serving routes/directions, up to the next three valid arrivals when supplied, update time/provenance, and alerts. Never fabricate missing arrivals.
- [ ] Provide walking directions to the actual verified boarding point, using task 5’s walking contract or an explicit external directions link until that contract is integrated.
- [ ] Expose save-stop actions integrated by task 7 and links to Plan. Support direct URLs for route and stop details and sensible Back behavior.
- [ ] Style current versus stale vehicle positions distinctly, with text explanations, and stop refreshing when the page is hidden if that fits the shared polling design. Clean up subscriptions/listeners.
- [ ] Handle map loading/failure, offline, no route selected, no service, invalid detail IDs, no GPS, overlapping markers, route changes, and mobile panel/map gestures.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build` pass. Add meaningful feature tests, including the cases below.

## Out of scope

- Custom tile hosting or a guessed route path reconstructed from unverified data.
- Transfers, private location tracking, or inferring route closures from missing buses.

## What we'll test

- A bus and a stop open the correct detail; route filtering preserves the right markers and colors.
- A loop repeats one physical stop, opposite directions share a stop name, and multiple vehicles overlap.
- Fresh, stale, absent, and malformed coordinates; old positions never appear as live.
- One/two/three arrivals, no predictions, a cancelled source prediction, unknown route IDs, and service after midnight.
- Direct URLs, browser Back, keyboard/list fallback, narrow touch panels, attribution visibility, failed tiles, and cleanup after navigation.
